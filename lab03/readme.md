# Лабораторная работа № 3. Настройка cron

## Назначение и ограничения

Автоматизация запуска `currency_exchange_rate.py` из лабораторной работы № 2. Скрипт скопирован без изменений. Сторонние библиотеки Python не нужны.

**Исходный клиент разрешает только даты 2025-01-01 — 2025-09-15.** Поэтому при запуске в 2026 году задачи cron выполняются, но получение курса завершается ошибкой даты с кодом 1. Для актуальных курсов нужны новые данные и адаптация клиента. Простое удаление проверки даты не решает проблему: учебный API подставляет последнюю запись вместо отсутствующей даты. Формула учебного API также сохранена без изменений; её результат не следует считать рыночным курсом конвертации.

## Расписание

Часовой пояс контейнера — `Europe/Chisinau`, включая переходы на летнее время.

| Cron | Действие |
| --- | --- |
| `0 6 * * *` | Ежедневно в 06:00: MDL → EUR за вчера |
| `0 17 * * 5` | По пятницам в 17:00: MDL → USD за прошлую календарную неделю |

Предыдущая неделя — понедельник–воскресенье перед текущей неделей. Поскольку исходный API принимает одну дату, обёртка выполняет семь отдельных запросов, без вычисления среднего. Например, в пятницу 2026-10-23 будут запрошены даты 2026-10-12 — 2026-10-18. Даты рассчитываются при выполнении задачи, включая границы месяцев и лет.

## Сборка и запуск

Требуются Docker Desktop с запущенным движком Linux-контейнеров и Docker Compose. Из корня репозитория:

```sh
git switch lab03
cd lab03
docker compose up -d --build
docker compose ps
```

Compose запускает планировщик и учебный PHP API в общей сети. Адрес API — `http://api/`; `localhost` внутри контейнера указывал бы на сам планировщик. Ключ по умолчанию — `EXAMPLE_API_KEY`.

Dockerfile устанавливает cron и tzdata. Entrypoint сохраняет нужные переменные в `/run/cron-env.json` с правами только для владельца, чтобы обёртка могла передать их клиенту независимо от окружения cron. Расписание устанавливается через `crontab`, поэтому столбец пользователя в `cronjob` не нужен. Демон cron запускается в фоне; entrypoint следит за ним и останавливает при завершении контейнера. Стандартный вывод и ошибки задач добавляются в `/var/log/cron.log`; новые записи также выводятся через `tail` в журнал контейнера.

## Проверка

```sh
docker compose exec scheduler date
docker compose exec scheduler crontab -l
docker compose exec scheduler cat /var/log/cron.log
docker compose logs -f scheduler
```

До первого срабатывания расписания журнал задач может быть пустым. Для ручной проверки на доступных исторических датах:

```sh
docker compose exec scheduler sh -c 'python -u /app/lab03/run_scheduled.py daily --today 2025-09-15 >> /var/log/cron.log 2>&1'
docker compose exec scheduler sh -c 'python -u /app/lab03/run_scheduled.py weekly --today 2025-09-12 >> /var/log/cron.log 2>&1'
docker compose exec scheduler cat /var/log/cron.log
docker compose exec scheduler ls -l /app/data
```

Первый запуск запрашивает 2025-09-14, второй — 2025-09-01 — 2025-09-07. В журнале должны быть время начала, дата запроса, ответ клиента и код завершения (0 — успех, 1 — ошибка). Ручной запуск проверяет API и запись результата, но сам по себе не подтверждает срабатывание cron.

Для проверки именно cron временно установите историческую задачу раз в минуту:

```sh
docker compose exec scheduler sh -c 'crontab -l > /tmp/cronjob.original'
docker compose exec scheduler sh -c 'echo "* * * * * /usr/local/bin/python -u /app/lab03/run_scheduled.py daily --today 2025-09-15 >> /var/log/cron.log 2>&1" | crontab -'
```

Дождитесь следующей минуты и проверьте журнал командой выше. Затем обязательно восстановите расписание:

```sh
docker compose exec scheduler crontab /tmp/cronjob.original
docker compose exec scheduler crontab -l
```

Остановка: `docker compose down`. Журнал и JSON сохраняются в именованных томах. Команда `docker compose down -v` удаляет тома вместе с результатами.

## Структура

| Файл или каталог | Назначение |
| --- | --- |
| `currency_exchange_rate.py` | Исходный клиент; сохраняет JSON в `/app/data` |
| `run_scheduled.py` | Расчёт дат, передача окружения и запуск клиента |
| `cronjob` | Два задания с перенаправлением вывода и ошибок в журнал |
| `Dockerfile` | Сборка образа Python с cron и установка расписания |
| `entrypoint.sh` | Подготовка окружения, запуск и контроль cron, вывод журнала |
| `docker-compose.yml` | Планировщик, API, общая сеть и постоянные тома |
| `.dockerignore` | Ограничение контекста сборки |
| `.gitattributes` | Окончания строк LF для Linux-скриптов и cron |
| `service/` | Копия API из `lab02`; основной запуск использует Compose в `lab03` |
| `lab02.md`, `image.png`, `результаты_проверки.json` | Материалы предыдущей работы, не результаты проверки `lab03` |
| `readme.md` | Инструкция по запуску и проверке |

Исходный клиент дополнительно записывает ошибки в `/app/error.log` в слое контейнера. Постоянный журнал заданий находится в `/var/log/cron.log`.
